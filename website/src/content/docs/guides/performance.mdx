## Rendering benchmarks

Each cell reports median translation time in nanoseconds and allocations per call on an Apple M3 Pro with Go 1.27.1 (darwin/arm64). Speedup is go-i18n time divided by go-intl time.

## How the cases were measured

The ten interpolation cases use the [v0.1.1 comparison](https://github.com/Waterkyuu/go-intl/releases/tag/v0.1.1). Each case used a single English message, a bound go-intl translator or warmed go-i18n localizer, and prepared arguments. The benchmark checked each translation before timing. Each implementation ran six times on one logical CPU, with 250 ms per case.

The static lookups and English plural use the original three-run medians. Their shared English dictionary had 1,024 static keys, a greeting, and a plural. The repeated lookup reads one key every time. The rotating lookup visits all 1,024 keys once per cycle.

## Bind once per view

Reuse the locale and translator across renders. In the original greeting benchmark, creating a fresh argument map on each call raised go-intl's time from 66 to 180 ns/op. Keep mutable values local to their goroutine. The immutable catalog can be shared by concurrent readers.

## Run the comparison

From the repository root, run all 13 cases against both libraries with Go 1.26 or later.

```sh
go test -C benchmarks -run '^$' -bench '^BenchmarkTranslation$' -benchmem -cpu=1 -benchtime=250ms -count=6
```

The [benchmark source](https://github.com/Waterkyuu/go-intl/blob/main/benchmarks/translation_benchmark_test.go) defines each case. The [performance report](https://github.com/Waterkyuu/go-intl/blob/main/PERFORMANCE.md) includes the original measurements, startup costs, parallel throughput, and profiling commands.
